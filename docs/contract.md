# 契约与积木规格

这份文档回答一个问题：**我要让角色做一个新动作，最少要动哪里，怎么知道没碰坏别的。**

契约 = 后端无关的那三样。换渲染器、加 3D、接 Remotion，动的都不该是它们。

## 1. 档期档案 `Episodes/<EP>/episode.json`

一集声明自己要什么，不写怎么画：

| 键 | 含义 |
| :-- | :-- |
| `actions` | 这一集会用到的动作名。后端没有实现的，装配前就打缺件报告 |
| `mover_actions` | 哪些动作会自己横向位移。站位变了但这些动作之外 → 报错（瞬移） |
| `screens` | 屏幕内容（电视里放什么）。`null` 表示不占屏幕 |
| `props` | 这一集能被点名的道具 |
| `stills` | 引用的外部图（按路径读原件，不在仓库里存副本） |
| `credits` | 哪个屏幕内容要署谁的名 —— 署名是**贴在质感层之后**的，否则会被线条抖动带着晃 |

## 2. 两层时间线 `Episodes/<EP>/Script.md`

顶部那段 ```json 是唯一事实来源，由 `BuildScript.py` 从稿子与实测配音生成，**别手改**。

- `speech[]` 口播层：配音与字幕，时长来自实测音频。
- `beats[]` 画面层：一拍 = 稿子里的一个括号指示。字段 `start / end / action / char_x / cues / screen`。

分两层的原因：**口播段数不等于画面拍数**。校验规则（缝与重叠、字幕最短可读时长、
站位与走路动作的匹配）都在 `Contract.py`，宁可 exit 也不凑合渲染 ——
段表和画面对不上时片子照样出得来，错只藏在某几秒里，那比失败更糟。

## 3. 通道词表

角色姿态是一组**有名字的连续量**，定义在 `Contract.REST`（19 个）：

```
rootX rootY rootRot          整体位移与旋转
shellX shellY shellRot       龟壳（刚体：只有平移与旋转，0% 形变）
bodyScaleX bodyScaleY bodyRot 躯干（流体：挤压拉伸发生在这里）
legLeftSquash legRightSquash legLeftRot legRightRot
headRot headY
armLeftRot armRightRot
eyeSquash mouthAperture
```

两条规矩：

- **名字属于契约**。门禁按名字判动作质量（`CheckMotion` 数每个通道的振幅与时长），
  所以换 3D 只换求值器，不改名字、不加只有某个后端才有的私有通道。
- **滞后是真滞后**：`LAGGED` 里的部件在 `t - lag` 处**回读**核心姿态，
  不是把结果乘个 0.9。旧实现 `shellY = rootY * 0.9` 实测相关系数 0.996 —— 那是齐步走，
  正是机械感的头号来源。

## 4. 加一块积木（一个动作原语）

1. 在 `episode.json` 的 `actions` 里声明这个名字（这一集要用的话）。
2. 在 `RenderVideo.py` 写 `_core_<name>(t, b0, b1, b)`，返回一份通道字典。三条硬约定：
   - **只认拍边界** `(t, b0, b1)`，不在函数里写死秒数 —— 段长变了动作才不会和画面对不上；
   - **从静止起、回静止落**（窗口首尾各通道归回 `REST`），拍与拍的接缝才天然连续；
   - 挤压拉伸**只施加在加速与接触事件上**，禁止常驻正弦；关键帧时刻跟着道具记号走
     （`Contract.cue_time(beat, prop, kind)`），不是"段长的几分之几"。
3. 注册：`CORE_FN["<name>"] = _core_<name>`。注册表会自动和档案对账。
4. 跑 `make check`。至少要看：`CheckMotion` 里这个动作的通道**有振幅、时长在档位内、
   各部件错峰**；如果这个动作会拿东西，加一条 `CheckPainted` 断言（见 §6）。
5. 若这个动作会改变横向站位，把名字也加进 `mover_actions`。

## 5. 后端要提供什么

契约只要求两件事：**注册自己的实现**，以及**给出一帧的像素**。

```python
K.implement("action", "dunk", _core_dunk)     # 编舞
K.implement("screen", "aura", _screen_content) # 屏幕内容的画法
K.implement("prop", "propBall", PROP_SVGS["propBall"])
K.assert_complete()                            # 与档案对账，缺件即 exit 1
```

对账按"**能不能画**"判，不按"有没有一份 SVG"判 —— 程序化画的道具（比如画在电视玻璃里的
界面）同样是实现。这条是我自己踩出来的：第一版把"没有 SVG"当成缺件，误报了一个。

## 6. 判据要能差分

新加的东西必须有一条"真的画到画面上了"的证据，做法是**渲两次再比像素**：
把某个记号关掉渲一帧、开着渲一帧，两帧之差就是它实际占的像素。
数量级不对（该出现的只出现 3 个像素）就是没画对。

`CheckPainted` 是这条思路的现成实现。加新积木时顺手加一条，比事后回看 116 秒视频便宜得多。

## 7. 确定性分级（跨后端时最容易翻车的一条）

`state = f(t)` 在每个后端上的"能复现"程度不一样，必须写清楚：

| 后端 | 复现级别 | 对拍判据 |
| :-- | :-- | :-- |
| PyMuPDF（现） | 逐位相同 | 同帧号两次渲染的 PNG 哈希必须一致 |
| Remotion（计划） | 帧级确定 | 同 `?t=` 取同一帧；像素允许编码损耗 |
| Blender/Cycles（计划） | **统计确定** | 固定 seed 与采样数之后，只能判"平均差异 < 阈值"，不能判逐字节 |

判据要跟着降级，否则换后端那天，所有门禁会同时"失败"，而画面其实没问题。
