# framelet

> 一帧一帧，把稿子变成片子。
>
> *A video tool where motion is a function, not a keyframe. Write the script,
> assemble actions, render. Built so that an AI can read the timeline and edit it too.*

**现在的状态**：2D 角色动画这条管线已经跑完一整期成片（116 秒、30fps、1920×1080、零手动关键帧）。
常规剪辑（trim / 拼接 / 多轨）和 AI 原生操作是下一步，见文末路线图。所以这个仓库现在
是一个**能用的动画渲染管线**，不是一个成熟的剪辑器 —— 别按剪辑器预期它。

---

## 主张

绝大多数"代码做动画"其实是在**用代码补间手工摆好的姿态**。这个项目反过来：

```
state = f(time, inputs, params)
```

角色每一帧的姿态是**当场算出来的纯函数** —— 没有关键帧表，没有累积状态，
同一帧号在任何机器上必须复现出同一份像素。动作不是"摆出来的"，是"参数与事件描述出来的"。

这样做的收益：可复现、可 diff、可回归测试 —— 也就是**软件工程那套质量手段第一次能用在了创作流程上**。
代价也很实在：超出词表的那一拍演不出来，只能加积木。所以本仓库最重要的东西不是渲染器，
是[契约与门禁](docs/contract.md)：它决定加一块积木要动几行、会不会碰坏别的。

## 30 秒上手

```bash
make venv                        # 建 .venv 并装依赖（ffmpeg 需自装：brew install ffmpeg）
make check                       # 资产 + 动作质量 + 出门前扫描，三条门禁
make frames                      # 抽三帧 PNG 到 Episodes/Demo/Render/frames/
```

跑的是 `Episodes/Demo/` —— 一个 8 秒、无配音的最小样例，用来看契约长什么样。

## 一集是怎么装出来的

```
稿子 (Voice.md)  →  口播稿 (Voice.en.md)  →  实测配音时长 (timing.json)
        ↓  Scripts/BuildScript.py
两层时间线 (Script.md 顶部那段 json)      ← 口播段数 ≠ 画面拍数，所以分两层
        ↓  Scripts/Contract.py 校验 + 与后端对账
逐帧姿态 = f(t)   →   SVG   →   光栅化   →   质感层   →   字幕   →   FFmpeg
```

- **档期档案** `Episodes/<EP>/episode.json`：这一集用哪些动作、哪些道具、哪张剧照、引用素材署谁的名。
  新增一集是填这张表，不是改代码：`make episode NAME=EP002_xxx`。
- **契约层** `Scripts/Contract.py`：时间线读取与校验、身体通道词表、编舞参数。后端无关。
- **后端** `Scripts/RenderVideo.py`：契约的第一个实现（PyMuPDF 光栅化 + FFmpeg 管道）。
  Remotion 版是计划中的第二个实现 —— 它 import 同一份契约，不重新发明时间线。
- **门禁** `Scripts/Check*.py`：见下一节。

## 门禁：这个项目里最值得抄走的部分

动画的失败通常是**静默**的：算对了但没画出来、字体取不到就退成方框、字幕压在画面外。
所以每条判据都必须能跑，而不是"我看着挺好"。

| 门禁 | 它拦的是什么 |
| :-- | :-- |
| `CheckMotion` | 零振幅的死通道、单帧跳变、各部件齐步走、段边界幻影甩手 |
| `CheckPainted` | **算到了不等于画到了** —— 同一帧渲两次做像素差分，证明段表里那个记号真的出现在画面上 |
| `CheckAsset` | 光栅化器会**静默丢弃**的 SVG 特性（`filter` / `clip-path` / 渐变），以及 rig 与资产的 id 错配 |
| `CheckSync` | 改过台词没重配音、音轨与段表时长不符、有字无声、画面记号抢拍 |
| `CheckRender` | 成片本身：规格、流时长闭合、尾部静音、空白帧 |
| `CheckProvenance` | 哪句是创作者原稿、哪句是 AI 改写的 —— 不许 AI 把语气磨平 |
| `CheckPublish` | 哪些文件绝不能进公开仓库（配音样本、剧照、密钥） |

`CheckPainted` 的由来值得单说：一个道具在段表里被点名、代码里也算出了位置，画面上却没有它——
因为换行符、坐标系或裁剪把那一笔丢了。**"看起来绿了"和"画出来了"是两件事**，
这条门禁的存在就是为了不让前者冒充后者。

## 路线图

1. **装配回路**：一个能拖时间、立刻看到某一拍的预览窗口（走 Remotion，与现后端对拍同一集）。
2. **积木变多**：动作原语的规格与注册方式（`docs/contract.md`），让"加一个动作"是加一块积木而不是改渲染器。
3. **3D 资产**：Blender 建模 → 同时导出给 2D 后端用的图形和给 3D 后端用的模型。通道名保持不变，只换求值器。
4. **常规剪辑**：trim / 拼接 / 多轨 / 音量包络，复用同一份时间线契约 —— 剪辑和动画在契约层是同一件事：对帧和时间点动手。
5. **AI 原生操作**：时间线是可读写的 JSON、动作是带声明的注册表、质量是机器判据 —— 这三样齐了，AI 才谈得上"参与制作"而不是"生成一堆没人能改的东西"。

## 名字

`framelet` = frame + `-let`（指小后缀）。帧的最小可操作单位 —— 动画和剪辑说到底都在对它动手。
（数学里 framelet 是小波的一个变体名，不是本项目首创；这里取的是字面意思。）
